公地引擎 · 核心业务流程图

5 条核心业务链路 · 从成员注册到争议救济的全生命周期

① 成员生命周期

  • • 注册 → 验证 → 角色分配 → ACTIVE
  • • 触发全域参与 (治理/支付/互助)
  • • SUSPENDED (违规) → WITHDRAWN (退出)

② 提案投票

  • • 强制审议: 定价/匹配/解雇/开除
  • • AI 多角色交叉审议 → 四院投票
  • • PASSED → Outbox 事件 → 跨域执行

③ 支付结算

  • • 事件溯源: CHARGE → SETTLE → FEE
  • • 反榨取校验贯穿始终
  • • Outbox 保证跨域最终一致

④ 匹配调度

  • • Redis Geo 替代 PG 位置查询
  • • 多因子评分 + 反榨取过滤
  • • 可解释排序，算法透明

⑤ 争议三级救济

  • • L1 业务复核 → L2 申诉委员会 → L3 仲裁
  • • 每级不满意可上诉升级
  • • 争议激增联动预警系统

跨域通信

  • • 当前: 同进程方法调用
  • • 未来: Outbox + MQ 异步
  • • ACL Facade 防腐层已规划
